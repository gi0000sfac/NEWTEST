# AI‑INSTR (Central Instruction for AI / LLM Pipelines)

> **이 파일은 모든 문서가 공통으로 참조하는 "중앙 관리용" 규칙집입니다.**\
> 이제부터 개별 문서는 **하나의 HTML 주석**만 남기고 이 파일을 참조합니다.

```html
<!-- AI-INSTR-REF: /_ai/AI-INSTR.md -->
```

위와 같이 **파일 경로만** 넣으면 됩니다. 버전 앵커·YAML 키 모두 필요 없습니다.

---

## 0. 적용 대상 & 참조 방식

| 구분            | 내용                                                                 |
| ------------- | ------------------------------------------------------------------ |
| **적용 대상**     | VitePress로 빌드되는 모든 Markdown/Raw HTML 문서, 이후 AI·챗봇·벡터DB에 투입되는 동일 원본 |
| **참조 표식(필수)** | `<!-- AI-INSTR-REF: /_ai/AI-INSTR.md -->` *(HTML 주석 한 줄)*          |
| **참조 표식 위치**  | YAML 아래 또는 문서 상단 아무 곳. 렌더링에 영향 없음                                  |
| **버전 관리**     | 이 파일 내부에서만 관리. 참조 표식은 **항상 동일**                                    |

> 문서 수백 개가 있어도 **표식은 한 번만 삽입**하면 끝. AI‑INSTR가 업데이트돼도 문서를 다시 고칠 필요 없습니다.

---

## 1. 목적

1. 문서 구조·메타데이터·표기 규칙을 AI/LLM 파이프라인이 **일관되게 해석**하도록 통합 관리한다.
2. VitePress 렌더링과 AI 파싱 간 **숨김/표시/색인 정책**을 통일한다.
3. 변환·빌드·검색 파이프라인에서 생길 수 있는 **오류·충돌의 우선 처리 규칙**을 정의한다.

---

## 2. 파싱 우선순위

1. **YAML Front Matter** → 파싱 후 본문에도 보존
2. **Markdown 본문**
3. **Raw HTML 블록** (정보성 유지, 순수 스타일은 AI 요약에서 제외 가능)
4. **무시 토큰**(`AI-IGNORE-START/END`) 사이 영역은 완전 무시

파싱 실패 시: 가능한 범위만 파싱하고 로그에 남긴다.

---

## 3. YAML 규칙

- 최상단 `---` … `---` 블록 하나만 허용.
- 모든 키/값을 그대로 보존·색인한다.
- 배열/객체 구조 유지.
- 주석은 `#` 사용. YAML 밖 설명 문장은 넣지 않는다.

---

## 4. 헤더·클래스 규칙

- 헤더 예: `## 제1조 (목적) {#article1 .sr-only}`\
  `{#id .class}` 문법(markdown‑it‑attrs)을 따른다.
- 숨김/표시 클래스:
  | 클래스         | 역할               | 렌더링 | 색인/요약 |
  | ----------- | ---------------- | --- | ----- |
  | `.sr-only`  | 시각적 숨김, 스크린리더 표시 | 숨김  | 포함    |
  | `.toc-only` | ToC 전용           | 숨김  | 제외    |
- 그 외 클래스·style 속성은 기본 무시. 단 `.sr-only`, `.toc-only`는 예외.

---

## 5. 조문(법령) 구조 패턴

1. 숨김 헤더(목차용): `## 제n조 (제목) {#artN .sr-only}`
2. 본문 표제: `**제n조 (제목)**`
3. 조문 전문

중복 텍스트 허용, 항/호 기호(①, 1., 가. 등) 유지.

---

## 6. RAW HTML 처리

- 정보성 HTML은 삭제하지 않음.
- 순수 레이아웃/스타일용 DIV·SPAN은 AI 요약에서 제외 가능.
- 열려 있지 않은 태그가 있으면 가능하면 닫는다.

---

## 7. 무시 토큰

```text
AI-IGNORE-START
(이 구간은 검색·요약·QA에서 제외)
AI-IGNORE-END
```

- 중첩 금지.

---

## 8. 청크 분할

- 권장 길이: 1 000–2 000 tokens.
- 분할 우선순위: (1) 조·항·호 → (2) 문단 → (3) 임의 분할.

---

## 9. 오류·우선순위 규칙

1. YAML > 무시토큰 > 헤더/숨김 > 기타 스타일
2. 오류는 로그 후 가능한 범위 파싱.
3. 충돌 시 **이 파일의 최신 규칙**을 우선.

## 10. 버전 관리 (내부용)

- 파일 상단에 `AI-INSTR vYYYY-MM-DD` 표기 + Change Log 추가.

- **문서 참조 표식은 바꾸지 않는다** → 업데이트 시에도 크롤러가 최신 내용을 자동 취득.

  네. 모든 문서는 고정 문자열 `<!-- AI-INSTR-REF: /_ai/AI-INSTR.md -->` 만 유지하면 됩니다.
