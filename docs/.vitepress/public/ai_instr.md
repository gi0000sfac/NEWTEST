# AI‑INSTR (Central Instruction for AI / LLM Pipelines)

> **이 파일은 모든 문서가 공통으로 참조하는 "중앙 관리용" 규칙집입니다.**\
> 개별 문서는 이 파일을 직접 포함하지 않고 **참조 표식만 남깁니다.**

---

## 0. 적용 대상 & 참조 방식

- **적용 대상**: VitePress로 빌드되는 모든 Markdown/Raw HTML 문서 + 이후 AI/챗봇/벡터DB에 투입되는 동일 원본.
- **참조 방법(문서마다 최소 표식 삽입)**
  - YAML 키 예시:
    ```yaml
    ai_instr_ref: "/_ai/AI-INSTR.md#v{{VERSION}}"
    ```
  - HTML 주석 예시(백업):
    ```html
    <!-- AI-INSTR-REF: v{{VERSION}} /_ai/AI-INSTR.md#v{{VERSION}} -->
    ```
- **경로/버전 변경 시 원칙**: 기존 앵커(`#{버전}`)는 삭제하지 않고 새 버전을 추가합니다.

---

## 1. 목적(Purpose)

1. 문서의 구조·메타데이터·표기 규칙을 AI/LLM 파이프라인이 **일관되게 해석**하도록 지시한다.
2. VitePress 렌더링과 AI 파싱 간의 **숨김/표시/색인 정책을 통일**한다.
3. 변환/빌드/검색 파이프라인에서 발생할 수 있는 **오류·충돌에 대한 처리 우선순위**를 정의한다.

---

## 2. 파싱(Parsing) 우선순위

1. **YAML Front Matter** (메타데이터) → 파싱 + 본문에도 보존
2. **Markdown 본문**
3. **Raw HTML 블록** (가능하면 정보 추출; 스타일 전용은 제외 가능)
4. **무시 토큰(AI-IGNORE-START/END)** 사이 영역은 완전 무시

> 파싱 실패 시: 가능한 범위만 파싱하고, 오류를 로깅한다.

---

## 3. YAML 규칙

- 최상단 `---` 로 시작하고 `---` 로 종료하는 **1개 블록**만 허용.
- 모든 키/값은 **원형 그대로 보존**하고 색인/요약에 활용한다.
- 배열/객체는 구조를 유지한다. (예: `amendments: [ {type: "개정", date: "2019-12-31"}, ... ]`)
- 주석은 `#` 사용. YAML 블록 외부의 설명 문장은 넣지 않는다.
- 오류 발생 시 **문서 파싱 중단 금지**(가능한 값만 파싱) — *파서별 동작 차이는 있을 수 있으므로 구현 측에서 보완 필요*.

---

## 4. 헤더·앵커·클래스 규칙

### 4.1 헤더 형식

```
## 제1조 (목적) {#article1 .sr-only}
```

- `{#id .class1 .class2}` 형식을 사용 (markdown-it-attrs 기준)
- ID는 문서 내 고유해야 함.

### 4.2 숨김/표시 클래스 정의

| 클래스         | 의미               | 렌더링(화면) | 색인/요약 | ToC   | 비고       |
| ----------- | ---------------- | ------- | ----- | ----- | -------- |
| `.sr-only`  | 시각적 숨김(스크린리더 전용) | 숨김      | 포함    | 포함    | CSS 필요   |
| `.toc-only` | 목차 전용(본문/요약 제외)  | 숨김      | 제외    | 포함    | 필요 시 사용  |
| (기타)        | 스타일 목적           | 기본 무시   | 기본 무시 | 기본 무시 | 예외 조항 없음 |

> **예외 보존 클래스**: `.sr-only`, `.toc-only` 는 style/class 무시 규칙에서 제외하고 **그 의미를 그대로 유지**한다.

---

## 5. 조문(법령) 구조 패턴

각 조문은 아래 패턴을 따른다:

1. **숨김 헤더(목차용)**: `## 제n조 (제목) {#artN .sr-only}`
2. **본문 표제**: `**제n조 (제목)**`
3. **조문 전문**: 일반 텍스트/목록 등 그대로 기술

- 중복 텍스트(1과 2)는 허용. AI 요약/검색 시 중복 제거 가능.
- 항/호/목 표기(①, ②, 1., 2., 가., 나.)는 원문 그대로 유지한다.

---

## 6. RAW HTML 처리

- 정보 전달(표 구조, 의미 있는 마크업)을 포함한 Raw HTML은 삭제하지 않는다.
- 순수 레이아웃/스타일 목적의 DIV/SPAN은 AI 요약에서 제외 가능.
- 닫히지 않은 태그, 잘못된 중첩은 렌더러마다 위험하므로 **가능하면 모두 정상적으로 닫는다.**

---

## 7. 무시 토큰 (Ignore Tokens)

- **형식**:
  - 시작: `AI-IGNORE-START`
  - 종료: `AI-IGNORE-END`
- 두 토큰 사이 텍스트는 모든 AI/LLM 파이프라인에서 **완전히 제외**한다.
- **중첩 금지**: START\~END 범위 안에 또 다른 START가 오면, 첫 START부터 마지막 END까지 전체 무시한다.

예시:

```text
AI-IGNORE-START
이 구간은 검색/요약/QA 모두에서 제외
AI-IGNORE-END
```

---

## 8. 청크(Chunk) / 토큰 분할

- **권장 청크 길이**: 1,000\~2,000 tokens (모델/DB 특성 따라 조정 가능)
- 분할 기준 우선순위: (1) 조/항/호 단위 → (2) 문단 단위 → (3) 임의 토큰 수
- 청크 메타에 `doc_id`, `article_id`, `chunk_index` 등 기본 키를 부여할 것(실제 구현부 책임).

---

## 9. 오류 처리 & 우선순위 규칙

1. **우선순위**: YAML > 무시토큰 > 헤더/숨김 규칙 > 기타 스타일
2. 파싱 오류(예: YAML 불량, HTML 깨짐)는 **로그 후 가능한 범위 파싱**.
3. 규칙 충돌이 발생하면 본 파일의 최신 버전 규칙을 따른다.

---

## 10. 버전 관리(Versioning)

- 이 파일의 상단에 `v{{VERSION}}` 를 명시한다. (예: 날짜 기반 `v2025-07-24`)
- **Change Log** 섹션에 변경 요약(1\~3줄)을 남긴다.
- 구버전 규칙이 필요한 문서는 해당 버전 앵커를 계속 참조할 수 있도록 **과거 앵커는 삭제하지 않는다.**

---

## 11. 배포/접근 정책

- 본 파일은 모든 파이프라인(빌드/요약/검색)이 접근 가능한 경로에 둔다.
- 외부 검색엔진 노출을 원치 않으면 `robots.txt` 또는 비공개 저장소를 사용한다.
- 캐시 문제가 있는 엔진은 **버전 해시/쿼리스트링** 등으로 무효화 처리.

## 12. 예시 스니펫 모음

### 12.1 개별 문서 YAML 예시

```yaml
---
title: "서울특별시 재단법인 서울문화재단 설립 및 운영에 관한 조례"
doc_id: "RG-2023-12-29"
ai_instr_ref: "/_ai/AI-INSTR.md#v{{VERSION}}"
amendments:
  - { type: "제정", date: "2003-07-15" }
  - { type: "개정", date: "2019-12-31" }
---
```

### 12.2 본문 헤더 예시

```md
## 제1조 (목적) {#article1 .sr-only}
**제1조 (목적)** 이 조례는 ... 규정함을 목적으로 한다.
```

### 12.3 무시 토큰 예시

```text
AI-IGNORE-START
개인정보, 내부 메모 등 외부로 노출되면 안 되는 내용
AI-IGNORE-END
```

## 13. FAQ (선택 삽입)

- **Q. **``** 꼭 써야 하나요?**\
  A. 사용 계획이 없으면 쓰지 않아도 됩니다. 의도 분리가 필요할 때만 사용하세요.
- **Q. YAML 에러가 나면 어떻게 하나요?**\
  A. 변환/빌드 스크립트에서 오류 감지 시 로그를 남기고 가능한 값만 파싱하도록 구현하세요.

  A. 정책에 따라 다릅니다. 재현성이 중요하면 고정 버전, 최신만 쓰려면 `latest` 앵커를 추가해 한 번만 표기할 수 있습니다.
